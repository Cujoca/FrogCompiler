Single-character punctuation tokens (; ( ) { } ,), the two-character operators (== != && ||), the single-character operators (= + - * / > < !) and the single-quoted character literal (e.g. 'A', handled as a fixed 3-character pattern) are recognized directly in the token-driven part of tokenizer() (Part 1) and never enter this DFA. The DFA below (Part 2) only recognizes the variable-length lexeme classes: identifiers / keywords / method names, integer & float literals, string literals and block comments.

2. Regular expressions of the variable-length token classes

  • VID_T / KW_T (variable identifier or keyword): L (L|D|U)*
  • MNID_T (method/function-name identifier – lexeme includes the trailing paren): L (L|D|U)* (
  • INL_T (integer literal, ≤ 5 digits, 0…32767): D D D D D capped, i.e. D1..5
  • FPL_T (float literal – a decimal point requires at least one following digit): D+ . D+
  • STR_T (string literal): " ( ¬" )* "
  • CMT_T (block comment): / * ( ¬* | * ¬/ )* * /

3. Final transition diagram (DFA)

Solid black arrows = normal transitions. Dashed red arrows = transitions into an error sink (ESNR/ESWR). Double-ringed nodes = accepting states (green = valid token, red = error token). "(retract)" means the triggering character is pushed back into the source buffer before the accepting function runs (FSWR); "(no retract)" consumes it (FSNR).

4. Notes on states reachable only outside the DFA proper

  • Division vs. comment (S0/S6/S7/S15): a lone / is recognized directly in tokenizer()'s token-driven switch as ARI_OP_T (division); only when it is immediately followed by * does the scanner hand off into state S6 (comment body) – the DFA's own S0→S(9) column is therefore dead in practice, which is why it is wired to the error sink.
  • FS (sentinel, value 16): not drawn as a node – it marks a transition-table cell that must never be reached (assert(next != FS) in nextState()). Every reachable input from every state lands on a real state, an accepting state, or one of the two error sinks above.
  • Fixed-length tokens bypassing the DFA entirely: ; ( ) { } ,, = == != && || ! + - * / (single/double char operators) and the character literal 'c' are all matched by dedicated case labels in tokenizer()'s Part 1 before the DFA (Part 2, this diagram) ever runs.
