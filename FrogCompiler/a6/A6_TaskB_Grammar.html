CST8152 – A6 Task B: Grammar Update

Language: Frog · Source: Step4Parser.h / Step4Parser.c (34 tracked BNF rules, recursive-descent, LL(1)) · Authors: Leo Paquette & Andrei Cojocaru

1. Grammar overview (top-level derivation flow)

Every statement category ultimately bottoms out in <expression> (a condition, an initializer, a return value, or an argument), and <unary> (the base of the expression chain) can itself contain a <call>, which is why callStatement feeds back into the expression chain rather than being a dead end.

2. Full BNF, grouped by category (all 34 tracked rules + tail helpers)

Program Structure

<program> →
  <opt_comment> <functionDefs>
↓
<functionDefs> →
  <opt_comment> <functionDef> <functionDefs> | ε
↓
<functionDef> →
  <type> MNID_T <optParams> ) { <opt_statements> }
↓
<optParams> → <paramList> | ε
<paramList> →
  <type> VID_T <paramListPrime>
<paramListPrime> →
  , <type> VID_T <paramListPrime> | ε
<type> → tadpole | lilypad | croak | ribbit | bullfrog
<comment> → CMT_T

Statements & Declarations

<opt_statements> → <statements> | ε
<statements> → <statement> <statementsPrime>
<statementsPrime> →
  <opt_comment> <statement> <statementsPrime> | ε
↓
<statement> →
  <varDeclaration> | <returnStatement> |
  <doWhileStatement> | <whileStatement> |
  <ifStatement> | <assignOrExprStatement> |
  <notStatement> | <outputStatement> |
  <inputStatement> | <callStatement>
↓
<varDeclaration> →
  <type> VID_T <optInit> ;
<optInit> → = <expression> | ε
<assignOrExprStatement> →
  VID_T = <expression> ; | VID_T <exprTail> ;
<notStatement> → ! VID_T ;
<returnStatement> → leap <optReturnValue> ;
<optReturnValue> → <expression> | ε

Control Flow

<ifStatement> →
  if <expression> then { <opt_statements> } <optElse>
<optElse> →
  else { <opt_statements> } | ε
↓
<whileStatement> →
  hop <expression> { <opt_statements> }
↓
<doWhileStatement> →
  do { <opt_statements> } hop <expression> ;

Both loop forms share the hop keyword; position (leading vs. trailing) disambiguates pre-test from post-test.

Input / Output

<outputStatement> →
  print( <outputVariableList> ) ;
<outputVariableList> → STR_T | VID_T | ε
↓
<inputStatement> →
  input( VID_T ) ;

MNID_T's lexeme already includes the trailing ( (see funcID() in the Scanner), so no separate LPR_T is matched after print / input / any user function name.

Calls

<callStatement> → <call> ;
↓
<call> → MNID_T <argList> )
↓
<argList> →
  <expression> <argListPrime> | ε
<argListPrime> →
  , <expression> <argListPrime> | ε

Expressions (precedence climb, low→high)

<expression> → <andExpr> <expressionTail>
<expressionTail> → || <andExpr> <expressionTail> | ε
↓
<andExpr> → <relExpr> <andExprTail>
<andExprTail> → && <relExpr> <andExprTail> | ε
↓
<relExpr> → <addExpr> <relExprTail>
<relExprTail> → (>|<|==|!=) <addExpr> | ε
↓
<addExpr> → <mulExpr> <addExprTail>
<addExprTail> → (+|-) <mulExpr> <addExprTail> | ε
↓
<mulExpr> → <unary> <mulExprTail>
<mulExprTail> → (*|/) <unary> <mulExprTail> | ε
↓
<unary> → ! <unary> | - <unary> |
  VID_T | INL_T | FPL_T | STR_T | CHR_T |
  <call> | ( <expression> )

3. Formal syntax (complete, plain BNF)

<program>              -> <opt_comment> <functionDefs>

<functionDefs>         -> <opt_comment> <functionDef> <functionDefs> | e
<functionDef>          -> <type> MNID_T <optParams> ) { <opt_statements> }
<type>                 -> tadpole | lilypad | croak | ribbit | bullfrog
<optParams>            -> <paramList> | e
<paramList>            -> <type> VID_T <paramListPrime>
<paramListPrime>       -> , <type> VID_T <paramListPrime> | e
<opt_comment>          -> <comment> <opt_comment> | e
<comment>              -> CMT_T

<opt_statements>       -> <statements> | e
<statements>           -> <statement> <statementsPrime>
<statementsPrime>      -> <opt_comment> <statement> <statementsPrime> | e
<statement>            -> <varDeclaration>   | <returnStatement>
                            | <doWhileStatement> | <whileStatement>
                            | <ifStatement>      | <assignOrExprStatement>
                            | <notStatement>     | <outputStatement>
                            | <inputStatement>   | <callStatement>

<varDeclaration>       -> <type> VID_T <optInit> ;
<optInit>              -> = <expression> | e
<assignOrExprStatement>-> VID_T = <expression> ; | VID_T <exprTail> ;
<notStatement>         -> ! VID_T ;
<returnStatement>      -> leap <optReturnValue> ;
<optReturnValue>       -> <expression> | e

<ifStatement>          -> if <expression> then { <opt_statements> } <optElse>
<optElse>              -> else { <opt_statements> } | e
<whileStatement>       -> hop <expression> { <opt_statements> }
<doWhileStatement>     -> do { <opt_statements> } hop <expression> ;

<outputStatement>      -> print( <outputVariableList> ) ;
<outputVariableList>   -> STR_T | VID_T | e
<inputStatement>       -> input( VID_T ) ;

<callStatement>        -> <call> ;
<call>                 -> MNID_T <argList> )
<argList>              -> <expression> <argListPrime> | e
<argListPrime>         -> , <expression> <argListPrime> | e

<expression>           -> <andExpr> <expressionTail>
<expressionTail>       -> || <andExpr> <expressionTail> | e
<andExpr>              -> <relExpr> <andExprTail>
<andExprTail>          -> && <relExpr> <andExprTail> | e
<relExpr>              -> <addExpr> <relExprTail>
<relExprTail>          -> ( > | < | == | != ) <addExpr> | e
<addExpr>              -> <mulExpr> <addExprTail>
<addExprTail>          -> ( + | - ) <mulExpr> <addExprTail> | e
<mulExpr>              -> <unary> <mulExprTail>
<mulExprTail>          -> ( * | / ) <unary> <mulExprTail> | e
<unary>                -> ! <unary> | - <unary>
                            | VID_T | INL_T | FPL_T | STR_T | CHR_T
                            | <call> | ( <expression> )
e denotes the empty production (ε). <exprTail> inside <assignOrExprStatement> is shorthand for resuming the precedence chain directly at <mulExprTail><addExprTail><relExprTail><andExprTail><expressionTail>, since the leading VID_T was already consumed as the <unary> atom - it is not a separately tracked BNF rule, just how the grammar avoids re-deriving the same identifier as a fresh expression.
